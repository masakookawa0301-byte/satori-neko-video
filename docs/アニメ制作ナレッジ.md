# アニメ制作ナレッジ（中割りで動かす方法）

第3話「煩悩クッキング きのこ鍋の巻」で確立した、さとりねこを「本当に動かす」ための手順と注意点。

## 全体の流れ

1. **絵コンテ**：16コマ程度。絵柄の基準は `素材/03_きのこ鍋/絵コンテ_高解像度.png`
2. **原画**：動かすカットごとに2〜3枚（動きの区切り：構え → 当たる → 結果）
3. **中割り**：Google Colab（無料T4 GPU）で ToonCrafter が原画の間を自動で描く
4. **タイミング**：中割りのコマから「どれを何コマ見せるか」を決めて並べ直す（`scripts/anime/retime_cut.py`）
5. **仕上げ**：効果音・BGM（`scripts/make_sounds.py`）を入れてつなぐ

## 原画（ChatGPT / Codex）

- **絵柄をそろえるには、satori-neko プロジェクト（Codex）で描かせる。** 普通のチャットだと参照画像が見えず、猫の顔や頭身が変わりやすい
- 指示に必ず入れること
  - 絵柄の基準：絵コンテ（高解像度）と三面図 06
  - 構図の基準：絵コンテの同じ番号のコマを、そのまま横長に大きくする
  - 同じカットの中では、構図・猫の位置と大きさ・背景・小物は完全に同じ。変えるのは指定した部分だけ
  - 横長1536×1024、文字・擬音・効果線・残像・枠線なし、1枚ずつ別の画像
- 原画は2枚だと差が大きすぎて中割りが崩れる。**3枚（構え・当たる瞬間・結果）が基本**
- 「切れる」「倒れる」などの変化は、それが起きた状態の原画を必ず入れる。入れないと包丁ときのこのタイミングがずれる

## 中割り（Colab・ToonCrafter）

- ノートブック：`scripts/anime/satorineko_nakawari_batch.ipynb`（フォルダごとまとめて処理）／`satorineko_nakawari_maker.ipynb`（1カットずつ）
- 必ず「ランタイム → T4 GPU」。①準備に5〜10分、1カット約2〜3分
- 出力は 512×320（ToonCrafterの仕様）
- 新しいComfyUIでは次の2つの修正が必要（ノートブックに反映済み）
  - 起動オプションに `--disable-dynamic-vram`
  - DynamiCrafterWrapper の `init_empty_weights() if is_accelerate_available` を `if False` に置き換え
- 中割りは途中で背景ごと少しずれることがある → タイミング付けのときに位置補正する

## タイミング（昔のアニメ風）

- 24fpsで考える。残像の重ね合わせは汚くなるので使わない（描かれたコマだけ使う）
- 例：⑨包丁で切る（約1.7秒）
  - 構え 14コマ → 振り下ろし3コマ → 当たる（サクッ）3コマ止め → 刃が通る3コマ → まな板に届く（トン）→ 18コマ止め
- 動いた後の状態は戻らない（切ったきのこは元に戻らない）ので、同じ動きのループはしない。繰り返すなら次の原画を足す

## やらないこと（失敗したこと）

- 1枚の絵をプログラムで揺らすだけ → 紙芝居っぽくなる
- 16コマが1枚にまとまった絵をそのまま使う → 1コマが小さくてぼやける
- 上下2ポーズの間を残像（重ね合わせ）でつなぐ → にじんで汚い
- 背景を固定して手だけ切り貼り → つぎはぎが目立つ

## ファイルのやりとり

- パソコンとのやりとりはデスクトップの `satorineko_anime` フォルダ（ダウンロードフォルダは使わない）

# 追記：2026-11-26〜27 の検証で分かったこと

## いちばん大事なこと
- **崩れの原因はほぼ「原画」**。「切る前→切った後」が絵で分からない原画は、どの動画AIにかけても破綻する
- **1カット1動作**。「構える・切る・転がる」を詰め込まない。難しい動作は「構えのアップ →（音）→ 結果のカット」に分けてもよい
- 動いた後の「止め」を長くすると紙芝居っぽくなる。止めの間も、湯気・まばたき・揺れなど何かを動かす

## 道具の使い分け（実際に試した結果）
| 道具 | 向いていること | 注意 |
|---|---|---|
| ToonCrafter（Colab無料） | 原画2〜3枚のあいだを埋める | 512×320と小さく、途中のコマが崩れやすい。今後は基本使わない |
| Wan 2.2 5B（Colab無料） | 止め絵に湯気・草・揺れなど「その場の小さな動き」 | 2秒で約3.5分。後半で崩れることがあり、前半だけ使う／崩れを画面外に拡大で逃がす |
| Firefly Video（Adobe） | 実写のBロール | アニメの「物が変化する動き（切る等）」は苦手。実写でも切る動作が破綻した |
| **Seedance 2.5（Firefly内のパートナーモデル）** | 最初のフレーム＋指示文で、はっきりした動作 | ⑥で初めて「構え→切る→切れて転がる」がつながった。480p・5秒で225クレジット、720pで475 |
| Kling / Veo（Firefly内） | 物理的な動きに強いとされる | 未検証 |
| Sora（OpenAI） | — | 2026年4月にアプリ終了。使えない |

- Fireflyのクレジット：月4000（毎月18日に回復）。生成ボタン横に消費量が出るので、**生成前に必ず数字を確認**
- 「最初と最後のフレームをつなぐ」使い方は、変身・切り替わり向き。普通の動作は「最初のフレーム＋指示文」で作る

## うまくいった作り方（⑥石づき）
1. Codexに場面を**部品ごと**に描かせる（背景・きのこ切る前/後・石づき・左手・包丁を持つ右手・腕）。全部 1536×1024 で位置をそろえ、部品以外は白
2. 部品を重ねて「構えた瞬間」の最初のフレームを作る（白背景は端からつながった白だけ消す。猫は白いので全部消すと手が透ける）→ `scripts/anime/cutout.py`
3. Seedance 2.5 に最初のフレーム＋英語の指示文（誰が・何をする・カメラ固定・「手は白いまま、形と色は最後まで同じ」）
4. 部品はそのまま切り絵アニメ（After Effects）にも使える

## 外部の知見（YouTube「初心者でもAIアニメが作れる最適解ワークフロー」まとめより）
- 「絵を作るAI」と「動かすAI」の役割分担と、作る順番が大事。無駄なガチャを減らせる
- 企画は30秒・4カット程度から。「振り・きっかけ・展開・オチ」で組み、カットごとに動きを1つに絞る
- キャラクターシート（正面・横・顔アップ）を作り、動画AIに参照として渡すと顔ブレが減る
- 指示文は「誰が出るか・何が起きるか・カメラの動き・聞こえる音」の4点。崩れたら「顔・髪・服は最後まで同じ」と明記して作り直す
- 派手なカメラワークや演出を詰め込むほど崩れる
- 画像は安いので良いものを選ぶ。動画は720pで試してから必要なカットだけ高画質に
- 仕上げは人が編集で（AI 8割・人 2割）。テロップは後から入れる
- 実在の作品名・スタジオ名・キャラ・実在人物は使わない。AIで作ったことは明示する

## 仕上げ
- 小さいコマのぼやけは、アニメ用高画質化（Real-ESRGAN realesr-animevideov3、CPUで1コマ約3秒）で線がくっきりする → `scripts/anime/upscale_anime.py`
- ただし紙の質感まで消えるので、最後に全カット共通の紙の質感を重ねて統一する（build スクリプトの UP 指定時）
- コマ補間（RIFE等）は、わざとカクカクさせたアニメ部分には使わない（ぬるっとして安っぽくなる）

## Colabの注意
- 無料GPUは1台まで。別のノートを使う前に「ランタイムを接続解除して削除」
- 夜通しの放置は途中で止まることがある。見ていられる時間に回す
- 結果のzipはダウンロードフォルダに落ちる → デスクトップ `satorineko_anime` に移してもらう
